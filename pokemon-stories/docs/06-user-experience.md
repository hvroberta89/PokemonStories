# User Experience

## Purpose

This document defines the user experience principles of Pokémon Stories.

It describes how the application should feel, behave and support the Game Master throughout the entire storytelling process.

This document intentionally focuses on the user experience rather than specific screens or implementation details.

Navigation, layouts and individual pages are documented separately.

---

# Experience Vision

Pokémon Stories is not a productivity tool.

It is not an administration system.

It is not a database editor.

Pokémon Stories is a creative companion.

The application should inspire creativity, reduce cognitive load and allow the Game Master to focus on the story rather than the software.

The best user experience is one where the application almost disappears during gameplay.

---

# Experience Principles

Every interaction should support one or more of these principles.

---

## Story First

Everything revolves around the story.

The interface should present narrative concepts before technical concepts.

Users should think in terms of:

- Adventures
- Characters
- Locations
- Scenes
- Rewards

Not in terms of records, entities or forms.

---

## Creativity Before Configuration

The application should encourage creativity instead of asking for configuration.

Whenever possible:

- suggest
- infer
- generate
- simplify

instead of asking the user to complete another form.

---

## AI as a Creative Partner

Artificial Intelligence exists to remove creative friction.

The AI should:

- suggest ideas
- expand concepts
- generate alternatives
- help with improvisation

The AI must never become the storyteller.

Every generated idea remains optional until accepted by the Game Master.

---

## Progressive Disclosure

Do not overwhelm users.

Only show information that is relevant to the current task.

Advanced functionality should appear naturally when it becomes useful.

The interface should remain calm and approachable.

---

## Momentum Matters

Live storytelling has momentum.

The application must never interrupt it.

During gameplay:

- interactions should be fast
- dialogs should be minimal
- typing should be reduced
- confirmations should be rare

The Game Master should always stay focused on the players.

---

## Reward the Story

Rewards are emotional moments.

The application should celebrate achievements instead of treating them as data.

Examples include:

- catching a Pokémon
- earning a badge
- completing a quest
- discovering a new location

These moments deserve visual emphasis.

---

# The Five Experience Modes

The application is built around five distinct user modes.

Each mode represents a different mindset.

The interface should adapt accordingly.

```text
CREATE

↓

PREPARE

↓

PLAY

↓

COLLECT

↓

REMEMBER
```

---

# CREATE

## Purpose

Help the Game Master create an adventure.

This is the most creative phase.

The interface should encourage experimentation.

### Characteristics

- calm
- inspiring
- visual
- spacious
- exploratory

### Typical Activities

- Create Adventures
- Design Scenes
- Generate NPCs
- Build Locations
- Create Rewards
- Ask AI for ideas

The interface should never feel like filling out a form.

---

# PREPARE

## Purpose

Help the Game Master feel ready.

Preparation should build confidence rather than enforce completeness.

The application should identify missing pieces while still allowing gameplay to begin.

### Characteristics

- organized
- reassuring
- checklist-oriented
- lightweight

### Typical Activities

- Review Adventure
- Select Narrative Context
- Check Rewards
- Prepare printable assets
- Review important NPCs
- Start Session

The application should encourage preparation without becoming a blocker.

---

# PLAY

## Purpose

Support live storytelling.

This is the most important experience in the entire application.

Everything else exists to improve this moment.

### Characteristics

- fast
- distraction-free
- touch-friendly
- responsive
- lightweight

### Typical Activities

- View Current Scene
- Add Notes
- Ask AI for help
- Unlock Rewards
- Add NPCs
- Track Progress

The application should never compete with the players for attention.

---

# COLLECT

## Purpose

Transform gameplay into lasting memories.

Players should feel rewarded.

The Collection is more than progress tracking.

It represents the history of the campaign.

### Characteristics

- celebratory
- rewarding
- visual
- collectible

### Typical Activities

- View Pokédex
- Review Inventory
- Print Stickers
- Browse Achievements
- Reprint Rewards

Collections should encourage curiosity and excitement.

---

# REMEMBER

## Purpose

Preserve the story.

Sessions become memories.

The application helps transform notes into a lasting campaign history.

### Characteristics

- reflective
- narrative
- emotional
- organized

### Typical Activities

- Review Session Summary
- Approve World Updates
- Save new NPCs
- Update World Facts
- Prepare the next Adventure

This phase closes one story while naturally preparing the next.

---

# User Flow

The ideal experience follows this journey.

```text
Create Project

↓

Create Adventure

↓

Prepare Adventure

↓

Run Session

↓

Celebrate Rewards

↓

Review Summary

↓

Update World

↓

Create Next Adventure
```

Every completed adventure strengthens the campaign world.

---

# Emotional Journey

Each phase should evoke a different emotion.

| Phase | Primary Emotion |
|--------|-----------------|
| Create | Inspiration |
| Prepare | Confidence |
| Play | Focus |
| Collect | Excitement |
| Remember | Satisfaction |

The interface should reinforce these emotions through visuals, animations and interaction patterns.

---

# Mobile First

Pokémon Stories is designed primarily for phones.

During gameplay:

- one-handed operation should be possible whenever practical
- common actions should require minimal navigation
- reading should be comfortable without zooming

Desktop layouts extend the experience but never define it.

---

# Interaction Principles

## Three-Tap Rule

Frequently used actions should require no more than three interactions.

Examples:

- Add Note
- Unlock Reward
- Ask AI
- Advance Scene

Long workflows belong to preparation, not gameplay.

---

## Never Block the Story

The application must never stop gameplay because of:

- missing internet
- failed printing
- AI timeout
- synchronization
- incomplete optional information

The story always comes first.

---

## Celebrate Success

Positive moments deserve positive feedback.

Examples include:

- subtle animations
- achievement moments
- reward confirmations
- printed sticker notifications

Celebration should feel meaningful without becoming distracting.

---

## Respect Attention

Attention is the Game Master's most valuable resource.

Avoid:

- unnecessary popups
- repeated confirmations
- modal overload
- excessive notifications

Every interruption must justify itself.

---

# Accessibility

The application should be enjoyable for all users.

Support includes:

- readable typography
- sufficient contrast
- large touch targets
- keyboard accessibility where applicable
- screen reader compatibility

Accessibility should be considered from the beginning.

---

# Success Criteria

The user experience succeeds when:

- the Game Master prepares faster
- live sessions flow naturally
- AI feels helpful rather than intrusive
- players become emotionally invested
- campaign worlds evolve effortlessly
- rewards become memorable moments

The application should become a trusted companion rather than the center of attention.

---

# Final Principle

The best compliment Pokémon Stories can receive is:

> "I forgot I was using an app."

Because everyone at the table was focused on the adventure.
